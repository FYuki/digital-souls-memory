# 0022. キャラの知覚範囲は perceived_by で表す

- 日付：2026-10-20
- 状態：Proposed（ユーザーの決定と親エージェントの詳細判断を反映。文書のレビューは親エージェントが行う）
- 置換対象：[ADR 0006](0006-shared-ledger-and-perception.md) の知覚範囲の表し方

## 背景

Evidence は複数のキャラが共通で使う証拠台帳である。一方、キャラ別の派生記憶・内省は、
そのキャラが知覚した出来事だけを根拠にする必要がある。
従来の Session.participants と Turn.audience では、途中参加・退出やささやきのたびに
誰が知覚したかを正しく読み取ることが難しい。配信の視聴者・利用者の一覧を保持する設計も不要である。
知覚したかどうかと、その内容をどこで話してよいかは別の判断である。
2026-10-20 にユーザーは、知覚したキャラを発言ごとに明示し、開示は記憶の内容ごとに制御すると決定した。

## 決定

- Evidence はキャラを所有者として持たない共通台帳のままとする。
- Turn に perceived_by（知覚したキャラ ID の文字列配列）を持たせる。空配列を許容し、重複と空白のみの ID は拒否する。
  視聴者・利用者の一覧は持たず、発話・行為の主体は actor で表す。
- Core が Turn の登録時に perceived_by を確定する。Turn は追記専用（E1）であり、登録後に perceived_by を変更しない。
- M6 は「キャラ別の派生記憶・内省は、そのキャラが perceived_by に含まれる Turn からだけ作る。
  ただし actor がそのキャラ本人なら、そのキャラは常にその Turn を知覚する」とする。
  知覚判定は `character_id ∈ perceived_by または actor == character_id` である。
  自己発話は perceived_by が空でも落とさず、M3 を維持する。自己発話の抽出もゲート M5 を通す。
- どのキャラもいない場での発言も、perceived_by を空にして台帳に記録できる。
- Session.participants と Turn.audience を廃止する。Session は接続単位として
  session_id、started_at、ended_at、surface を持つ。surface は出典窓口の種別であり、
  取得したチャンネル・部屋などの場所の属性は持たない。
- 途中参加・退出、ささやき、DM、日記、配信の視聴者コメントは、すべて Core が発言ごとに perceived_by を決めて表す。
  途中参加後に過去の Turn の知覚範囲を広げない。窓口をまたぐ利用者 ID の同一人物への対応づけも Core の責務である。
- 人づてに聞いた話は「A が B に話した」という新しい Turn として B が知覚する。
  B は元の Turn を知覚したことにはならず、元の Turn の perceived_by は変えない。
- 想起した内容を何処で話してよいかは、既存の Fact／Preference の「キャラ間公開範囲」の方向で、
  記憶の内容ごとに制御する。取得場所や現在の場所による絞り込みは行わない。
- 視聴者コメントの全件記録と、キャラが反応したものだけを抽出する規則は維持する。
  Session の終了記録を追記式の別レコードにする方針（Issue #12 の追加要件）も維持する。

## 検討した案

- **participants／audience 方式**：Session の固定参加者では途中参加・退出を表せず、
  視聴者一覧を持てない場合にも適さない。audience の空配列を参加者全員と読む方式は、
  ささやきや誰も知覚しない発言の扱いを誤りやすいため採用しない。
- **参加・退出の記録方式**：発言時点の在席を復元できるが、ささやき・DM 等には別の規則が必要となる。
  Memory が参加履歴を再構成するより、実際の接続状況を知る Core が発言ごとに知覚したキャラを確定する方式を採用する。
- **メンバー変更ごとのセッション分割**：知覚範囲のために接続単位を分割し、同じ接続の履歴が断片化する。
  ささやきにも分割が必要となるため採用しない。
- **取得場所による開示制御**：チャンネル・部屋の属性を記録して開示を絞る案である。
  ユーザーが不要と判断した。知覚の出典と開示の判断を分け、開示は記憶ごとに制御する。

## 影響

- Session／Turn の純ドメイン、HTTP API、PostgreSQL アダプタと知覚範囲のクエリを変更する。
  キャラ別の抽出・想起・資料登録も同じ知覚判定を使う。取得順序は occurred_at、recorded_at、turn_id のままとする。
- Core は知覚したキャラ ID を登録時に渡す必要がある。Memory は在席や接続場所から補完しない。
- 後続の実装 Issue で Alembic revision 0004 を 0003（Issue #7）の上に積み、
  旧規則（audience が空でなければ audience、空なら participants）で既存の合成データを埋め戻してから旧列を削除する。
  downgrade は perceived_by を audience に入れ、participants を空にする。旧参加者一覧は完全には復元できない。
- 設計文書を先に変更する。実装済みの Evidence API と docs/evidence-api.md の契約変更は、後続の TAKT タスクで一緒に行う。
  この ADR の追加は実装済みを意味しない。
