# 0024. 同じ Fact の再表明は別の記憶にせず、既存の Fact への出典寄与として記録する

- 日付：2026-10-25
- 状態：提案
- 関連：[ADR 0001](0001-raw-turns-as-source-of-truth.md)、[ADR 0012](0012-retrieval-scoring-and-recency.md)、[ADR 0019](0019-phase1-deletion.md)、[ADR 0023](0023-extraction-unit-and-independent-evidence.md)、Issue #61・#65・#68・#71

## 背景

同じ subject・predicate・object（以下 SPO）の Fact が別の Turn で再び話題になると、[ADR 0012](0012-retrieval-scoring-and-recency.md) に従って既存の Fact を再強化する。現在の実装の流れは次のとおりである。

1. 再表明からも、新しい ID を持つ別の DerivedMemory（候補）を作る。
2. 投影のときに、同じ SPO の既存 Fact へ候補を「吸収」する。吸収した候補は superseded にし、`extends` の relation を残す。
3. 吸収先の Fact を「代表」と呼び、他の記憶から吸収済みの候補への relation は代表へ付け替える。

この方式では、次の4つの処理が同じ代表を選ぶ必要がある。

- 全体投影
- 影響範囲に限った部分再構築（#46）
- ID が変わる再抽出（#49）
- 作者削除による再計算（[ADR 0019](0019-phase1-deletion.md)）

epic→main 追加分の代替レビューを4ラウンド行った。そのたびに、代表の選び方がこれらの処理でずれる不具合（major）が見つかった。

| ラウンド | 内容 | 対応 |
| --- | --- | --- |
| 1 | ID 変更つき再抽出で更新が戻る | #61 |
| 2 | 部分再構築と全体投影で derives の採否が食い違う | #65 |
| 3 | 吸収された側の作者削除、自己吸収、閉包の拡大 | #68：代表の対応を `memory_representatives` に保存 |
| 4 | 多段の代表、retry、代表そのものの作者削除、0013 の downgrade での対応喪失 | #71 |

代表を保存しても、次の2つが残る。

- 代表を誰がいつ選ぶか
- 代表が消えたり変わったりしたときに、参照元・出典・時間属性をどう更新するか

その結果、投影・削除・再抽出のそれぞれに同じ判断が分散している。個別のケースを直し続けても収束する見込みが立たない。

再表明は記憶の内容を増やさない。増えるのは根拠（出典）と再強化の時刻だけである（[ADR 0012](0012-retrieval-scoring-and-recency.md)、[ADR 0023](0023-extraction-unit-and-independent-evidence.md)）。参照可能な別の記憶として残す必要はない。

## 決定

### 再表明の判定と記録

- 抽出ゲート（M5）が抽出候補を受理するとき、同じキャラの現在有効な Fact の中に同じ SPO のものがあるかを確かめる。現在有効とは、その時点で `valid_from ≤ now < valid_to` かつ superseded でないことをいう。
  - ある場合、その候補は**再表明**とし、新しい DerivedMemory を作らない。
  - 代わりに、その Fact への**出典寄与**を記録する。出典寄与は（キャラ、Fact の ID、出典 Turn、抽出元の Turn、occurred_at）からなる。
- 判定は、受理と同じトランザクションの中で、キャラ単位のロックを取ったうえで、保存済みの射影に対して1回だけ行う。投影・部分再構築・削除の再計算では、再表明の判定も代表の選び直しもしない。出典寄与は保存されたデータとして読むだけにする。
- 同じ抽出の中で、モデルが再表明の候補 ID を relation の参照先にした場合は、受理の時点でその参照先を既存の Fact の ID に書き換えて保存する。書き換えたあとは、候補 ID への参照を残さない。
- 同じ SPO の Fact があっても、現在有効でなければ（updates で閉じた、superseded になった、など）再表明とはしない。新しい版の Fact として扱い、旧版との関係はモデルの明示した relation で決める（P4）。
- SPO が異なる明示の `extends` は、これまでどおり履歴の relation として残す。再表明にはしない。
- Commitment と VerbatimAnchor は再強化の対象外であり（[ADR 0012](0012-retrieval-scoring-and-recency.md)）、再表明の扱いも受けない。

### 出典寄与からの値の決め方

Fact の次の値は、Fact 自身の出典と、残っている出典寄与から決める。

| 値 | 決め方 |
| --- | --- |
| source_turn_ids | Fact 自身の出典と、出典寄与の出典 Turn の和集合 |
| last_reinforced_at | 出典寄与の occurred_at の最大値。古い寄与が後から届いても時刻は戻さない（[ADR 0012](0012-retrieval-scoring-and-recency.md)） |
| independent_evidence_count | 和集合の出典に [ADR 0023](0023-extraction-unit-and-independent-evidence.md) の規則を当てて数え直す |

- Fact の valid_from、出自、Trust Tier は、出典寄与で変えない（G1〜G3）。
- 再表明の候補が既存の Fact より古い出来事を指していても、Fact の ID と valid_from は変えない。出典と再強化の時刻だけに反映する。

### 取り消し（再抽出・作者削除・retry）

- 出典寄与は、抽出元の Turn ごとに持つ。その Turn を再抽出・requeue したとき、または retry に入ったときは、その Turn 由来の出典寄与をいったん取り消す。再抽出が成功したら、もう一度判定して記録し直す。
- 出典 Turn を作者削除したときは、その Turn を含む出典寄与を取り消し、Fact の値を残った出典から計算し直す（[ADR 0019](0019-phase1-deletion.md)）。
- Fact 自身の出典がすべて削除されても、出典寄与が残っていれば、Fact は同じ ID のまま、残った出典を根拠として存続する。
  - 本文の再計算は [ADR 0019](0019-phase1-deletion.md) の再計算処理が行う。
  - 再計算できない場合は、その Fact を取り下げる。残った出典寄与は取り下げとともに無効にし、別の Fact へ移さない。
- 取り消すのは出典寄与だけではない。その抽出元の Turn が加えた作用もすべて取り消す。対象は次のとおりである。
  - 書き換えて保存した relation（updates・contradicts・derives など）
  - それによる旧 Fact の valid_to の終了と superseded
  - 再強化の時刻
  取り消したあとは、残った出典と relation だけから値を計算し直す。
- 出典寄与と作用は、（Fact、抽出元の Turn、出典 Turn）ごとに1件として持つ。同じ抽出処理のやり直し（retry・requeue・再送）は、別の Turn での再表明とは区別する。やり直しは前回の寄与を置き換えるだけで、寄与を足し増さない。根拠の数や再強化の時刻を、処理の回数で増やさない。
- 出典寄与の取り消しと Fact の計算し直しは、取り消しの原因になった処理と同じトランザクションで確定する。

### 既存の仕組みの置き換え

- #61・#65・#68 で入れた「代表」の仕組みは、この決定で置き換える。具体的には次の3つである。
  - 候補の吸収
  - 代表への relation の付け替え
  - `memory_representatives` 表
- #49 指摘3の「同じ抽出元で ID が変わった再抽出の relation の解決し直し」は残す。これは同じ Turn の候補の対応であり、再表明とは別の仕組みである。
- 既存データは migration（0014）で移行する。
  - 吸収済みの候補（`memory_representatives` の行と、同じ SPO の適用済み `extends`）は、代表の Fact への出典寄与に変える。
  - 吸収済みの候補 ID を参照する relation は、代表の Fact の ID に書き換える。
  - そのあと `memory_representatives` を削除する。
- 0014 の downgrade は、出典寄与が1件でもあれば拒否する。出典寄与から吸収の候補と relation を元の形に戻すことはできないためである。この制約は migration と docs/memory-api.md に明記する。

## 検討した案

- **代表の対応表（0013）を保ったまま直し続ける**：代表の決定を投影より先に行う構造へ組み替え、操作の列をたどる不変条件試験を加える必要がある。修正量が大きく、4ラウンドの経過から収束を見込めないため採用しない。
- **Phase 2 へ回し、Phase 1 では再表明を無視する**：再表明で再強化しないことになり、[ADR 0012](0012-retrieval-scoring-and-recency.md) の再強化規則を満たさないため採用しない。ADR 0023 の「重複した記憶の整理」（会話終了後の非同期処理）は、この決定とは別に Phase 2 で扱う。
- **Fact の ID を SPO から決める（同じ SPO なら同じ ID）**：updates で閉じたあとに同じ内容が再び話題になる場合（コーヒー → 紅茶 → コーヒー）に版を区別できないため採用しない。
- **再表明の判定を投影ごとに行う（現行）**：判定が全体投影・部分再構築・削除に分散し、結果が食い違う原因になったため採用しない。
- **原文・抽出した Fact・統合した表示を分ける（Hindsight の observation 方式）**：抽出した Fact を別々に残し、非同期の統合処理で、複数の Fact を参照する observation を作り直す方式である。これは ADR 0023 の「重複した記憶の整理」（会話終了後の非同期処理、Phase 2）に近い。往復ごとの抽出で再強化する Phase 1 の範囲を超えるため、ここでは採用しない。Phase 2 の設計で参照する。

### 他のシステムの扱い（2026-10-25 調査、判断の参考）

| システム | 再表明の扱い | 出典の削除・やり直し |
| --- | --- | --- |
| Graphiti（Zep の OSS、main 8ce6d63） | fact 本文と両端の entity が一致すれば、既存の edge を再利用する。出典の集合（episodes）には、未登録の episode を足すだけにする。この決定に近い | episode を削除すると、edge の出典から外す。出典が残れば edge を残し、空になれば削除する。要約は残った episode から作り直す |
| Hindsight | 抽出した fact は別々に保つ。非同期の統合処理で observation を作り、根拠の数（proof_count）は異なる元 fact の数で数え直す | fact の変更・無効化のときは、それに依存する observation を作り直す。入力の同一性（document_id）と処理の再送（operation_id）を区別する |
| Mem0（Platform／OSS） | 完全一致や近い言い直しは、追加の時点で重複を除いて2件目を作らない。より詳しい版へ統合するときは、古いレコードを残して canonical へリンクする | Turn ごとの出典や、独立した根拠の厳密な管理は確認できなかった |

この表から、次の点を読み取った（比較からの推論である）。

- 「既存の知識に複数の出典を足していく」形には、公開された先例がある。ただし、受理時の1回の判定、同じトランザクションでの確定、3経路の結果の一致までを保証している例は確認していない。
- Graphiti には、過去の版で次の問題の報告があった（getzep/graphiti#2034）。
  - 最初の出典を削除すると、別の出典が支える fact まで消える。
  - 削除した内容が要約に残る。
  - 削除した episode による無効化が残る。
  出典を外すだけでは足りず、その出典が加えた作用も取り消す必要がある。この決定の「取り消し」はこれを踏まえている。
- Hindsight は、同じ内容の別の機会と、同じ処理の再送を区別している。この決定でも、やり直しで寄与を足し増さない。

## 影響

- 不変条件「全体投影 ＝ 部分再構築 ＝ 作者削除後の再計算」は、設計上は構造として保たれる。どの経路も、保存された出典寄与を同じ規則で集計するだけになるためである。ただし、これは設計上の主張であり、実装が満たすかは試験で確かめる。受入条件には次を含める。
  - 操作の列（抽出・再表明・updates・retry・再抽出・作者削除）を組み合わせ、3経路の結果が一致することを確かめる試験
  - 並行する受理と削除の試験
  - 0013 からの移行の試験
- 部分再構築の閉包に、吸収連鎖や代表の参照元を加える必要がなくなる（#46 の影響範囲限定を保つ）。
- 抽出ゲートは、受理の時点で現在有効な Fact を SPO で引く。0010 の fact lookup 索引（`*_fact_lookup`）を使う。
- 実装は TAKT のタスク1〜2件を見込む。
  - 出典寄与の保存と受理時の判定、代表の仕組みの撤去、migration 0014
  - 取り消し（再抽出・retry・作者削除）と、それぞれの回帰試験。#71 の (a)〜(d) と、#61・#65・#68 の再現ケースを含める
- docs/domain-model.md の「検索と忘却」と docs/memory-api.md の「採否と時間更新」「永続性と失敗」を、この決定に合わせて書き直す。
