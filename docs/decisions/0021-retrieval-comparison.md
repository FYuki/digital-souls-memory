# 0021. 検索方式・埋め込みモデルの比較（採用保留案）

- 日付：2026-10-20
- 状態：Proposed

## 背景と比較条件

pg_bigm / PGroongaとbge-m3 / multilingual-e5-largeを比較し、検索方式とモデルの採否を検討する。
本書は実測結果とAIの推奨案であり、親エージェントによる承認・採用決定ではない。
Memory用6項スコア、45設定の独立tuning、分類ごと・各回100%の品質ゲート、
最大5件・UTF-8 1,500byte推定を実測前に固定し、旧Coreの0.52や同等帯0.002を流用していない。
ケース・gold・選定規則は測定中に変更していない。

## 観測結果

同一の固定PostgreSQL比較イメージでvector・pg_bigm・PGroongaを各run有効化した。

実モデルの全tuningは540 run・44,280ケース・88,560実呼出し、実行エラー0で完了したが、品質は全設定FAIL。
acceptanceは以下の結果だった。

| 組み合わせ | 各3回の結果 | p50 / p95 ms（回ごとの範囲） |
| --- | --- | --- |
| bge-m3 + pg_bigm | 品質FAIL、各26/55、実行エラー0 | 11.64–12.11 / 15.24–15.76 |
| bge-m3 + PGroonga | 品質FAIL、各26/55、実行エラー0 | 11.51–12.03 / 14.97–16.13 |
| multilingual-e5-large + pg_bigm | 各10/55の後に実行ERROR、品質判定不能 | 全件集計なし |
| multilingual-e5-large + PGroonga | 各10/55の後に実行ERROR、品質判定不能 | 全件集計なし |

bgeは同義語5/10・言い換え3/10・日英横断0/10で、長文や一部出典必須・指定順位も未達。
該当なし10/10、禁止ID返却0でも全体の品質FAILは変わらない。
ハーネス内p95は300ms/600ms以内だが、製品HTTP・ProvisionRecord書込みは未計測。

e5は長文898トークンに対し、llama.cppが指定ctx 2048を学習時上限512へ制限しHTTP 400を返した。
同じ制限は別の使い捨てコンテナでも再現した。長文の切り詰めや分割を導入しない比較条件では、全件の品質判定に到達できなかった。
これは品質FAILと区別した候補の実行制約で、評価コードの不具合と断定しない。

GPU事前確認、GGUF・稼働alias・次元・pooling・接頭辞、llama.cpp build/image、
DB拡張・image、実コマンド、CPU/RAM/VRAM、索引・作成時間、hash・各回結果・制約は
[実測記録](../reports/2026-10-20-retrieval-it2-host.md)とその新規証跡に保存した。

## 検討した案

- **multilingual-e5-large：今回の採用候補から除外**。文脈長上限は512トークンで、
  Memoryの長文Turn（接頭辞込み898トークン）をそのまま埋め込むとHTTP 400、n_ctx=512となった。
  分割で対応すると比較の前提が変わるため、今回の比較では分割を導入しない。
  bge-m3は長い入力を扱え、今回のacceptanceを全件実行できた。
- **bge-m3 + pg_bigm / PGroonga：採用保留**。両方式で全件実行できたが、各26/55で品質未達。
  pg_bigmの索引中央値16 KiBはPGroongaの約33.4 MiBより小さく、索引作成時間・DB資源も小さかった。
  小さな合成ケースの資源差だけで全文検索方式の採否を決めない。

## 未決事項

ADR 0021は **Proposedのまま** とする。
[品質乖離の調査](../reports/2026-10-20-retrieval-quality-gap.md)によると、主な説明要因は、
合成スコアに対して高い閾値を選ぶtuning規則と、Coreとは異なる検索・採点条件である。
Coreの61/62は回答品質であり、検索は各回53/62、移設した共通55 IDでは46/55だった。
Coreの0.52は単位ベクトル間の二乗L2から求めるrelevanceへの閾値で、cosineやMemoryの合成スコアとは異なる。
Memoryの不合格29件は、適格な正解がある空結果28件と、正解全包含だが全順序が異なる1件。
空結果の直接の除外段階は合成閾値0.75だが、閾値前成分が未保存のため低閾値でのacceptanceの効果は未確定。
今回の確認範囲で評価仕様と実装の不一致は特定しておらず、実装不具合と断定しない。

次の条件を再評価する必要がある。

- **選定規則**：失敗条件の加算は、同じケースの禁止IDとno_matchを別々に数える。
  空結果は主にrecallの1違反となり、空結果を選びやすい非対称性がある。
  tuningのsemantic 0.75では、閾値0.60が54/82・44違反、0.75が40/82・43違反で後者が選ばれる。
  ケース単位の品質失敗と安全ゲートの役割を再検討する案があるが、禁止情報の扱いを弱めるリスクがある。
  低閾値の禁止22件・no_match16件は残るため、0.60を推奨採用値にはしない。
- **尺度・グリッド**：6項加重和を保持し、合成尺度に合わせた閾値の細分化と語彙重みを再評価する案。
  保存済みtuningの閾値0.20では全適格候補を保持しており再採点できるが、acceptanceの効果は再実行が必要。
  誤取得増加・過適合のリスクがあるため、acceptanceを使って調整しない。
- **実モデル順位ゲート**：決定的な完全同点ID順と実モデルの全順序を分ける案。
  順位条件だけを外す仮定では保存済みacceptanceは27/55で、依然FAIL。
  事後の緩和を避け、製品の順序要件を先に確認し、fixtureの順位検証を保持する。
- **goldの意味**：独立Fact検索とCoreのEpisode添付、更新Fact、必須原文区間をM2に照らして再承認する案。
  成績を上げるため正解・禁止IDを変更しない。現goldの失敗を保持し、変更効果は未算出とする。
- **分類ゲート**：Coreの各回90%とMemoryの100%の役割を明文化する案。
  現在の同義語5/10・言い換え3/10・日英0/10は90%でもFAILであり、ゲート緩和だけでは乖離を解消しない。

提案の根拠・効果・リスク、追加計測案と実施記録は調査報告を参照する。
条件変更を採用する場合は新しい比較版を測定前に固定し、旧証跡を保持する。

2026-10-20のユーザー決定を、次の比較版 **memory-v2の前提** とする。

- 取りこぼさないことを優先する。
- スコアはレンジで評価する。
- 含まれるべきデータが上位n件に含まれるかで判定し、1位であることは求めない。
- 他モデル（追加の埋め込みモデル・reranker）を比較する。

memory-v2ではn=5とし、安全（各回100%）と品質（想起分類は各回90%以上、
該当なし分類は各回70%以上）を分離する。thresholdの正解あり・該当なし側は別に評価する。
実モデルの全順序一致は合否に用いず、完全同点のID順は合成fixtureで確認する。
安全禁止と品質上の誤取得は固定goldで区別し、適格性による検索前除外、原文・出典・
返却予算の正しさを安全条件とする。正解欠落だけでは安全違反としない。
安全違反0の設定から、分類・回ごとの最低想起合格率、最低該当なし合格率、
平均recallの順で選び、完全同率なら固定グリッドの先頭を選ぶ。
分類別・回別に閾値前の全適格候補から正解と各ケースの非正解最高値の
最小・p05・p50・p95・最大を報告する。分位点は線形補間とし、個々の厳密値を品質条件にしない。
6項加重和・係数合計1・新しさ係数0.1以下、最大5件・1,500トークン相当は維持する。
任意のrerankerは順位だけを決め、閾値には6項合成スコアを使う。
追加候補のrevision・SHA-256・文脈長・pooling・接頭辞・量子化・次元は実測前に確定する。
具体的な採用モデルと採用閾値・重み、acceptanceへの効果は未決とする。

全文検索方式（pg_bigm / PGroonga）も採用保留とする。選ばれたlexical重みは0.05で、
今回の条件では方式間の品質差が出なかった。方式の採否は原因調査・再評価後に決める。
26/55の品質未達や資源差だけでbge-m3 + pg_bigmを採用しない。

## 採用判断の条件

採用方式・モデル・次元は未確定。本書の推奨案を採用決定として扱わない。
比較用イメージでの拡張の同居と、製品への採用判断は区別する。
bge基準はQ8_0 / CLS / 1024次元 / 接頭辞なし、revision
`9eba04c5d75ba5a1595e45de734d36bef4e5cb98`、SHA-256
`aa473d51f451a22f0fcf39ba3330c14bed38a385712b1113440f69df4047a173`。
e5比較条件はQ8_0 / mean / 1024次元、`query: ` / `passage: `（末尾空白）、revision
`272a0975bd1a67886c0719767af84dfd2cbd9aa4`、SHA-256
`6fc086a43fa9f9a766ee664312ecf2f301ff24c89f866c64936e5b4c5099b3be`。
モデルの条件は revision・ファイルhash・稼働サーバー情報を含む実測記録を参照する。

e5は今回の採用候補から除外し、bge-m3の品質乖離は原因を確認してから再評価・採用判断へ戻す。
固定goldを実測結果に合わせて変更しない。比較対象は151元ID、137 Memory入力、14の適用不能部分とその代替テスト、15境界ケースからなる。ケースの出典・適用不能部分・代替条件は実測記録を参照する。
Coreケースのライセンス表示は未特定で、配布可否は判断待ちとする。
ST・実運用規模・製品全体性能・e5全件acceptanceの受入は、この比較の観測範囲に含めない。
実測記録だけで検索方式・モデルの採用を承認したとは扱わない。
