# 0021. 検索方式は bge-m3 + pg_bigm + bge-reranker-v2-m3 による棄却とする

- 日付：2026-10-20（Proposed）、2026-10-21（承認）
- 状態：承認。追補 2026-10-28（長い原文のチャンク索引、本人決定）、追補 2026-10-30（閾値の既知の限界と保留した性能対策、本人回答 Q-008・Q-009）
- 関連：[ADR 0007](0007-postgres-single-store.md)、[ADR 0012](0012-retrieval-scoring-and-recency.md)、[ADR 0017](0017-recall-latency-budget.md)

## 背景と比較条件

永続ストア PostgreSQL + pgvector と共存する日本語全文検索方式、埋め込みモデル、
任意の reranker の採否を検討した。取りこぼさないことを優先し、スコアはレンジで評価する。

両比較版に共通の品質ゲートは次のとおり。

- 安全は各分類・各回100%。検索前の適格性、禁止情報の不在、原文区間・出典・話者・言語、返却予算を守る。
- 想起分類は、必須正解すべてが上位5件に含まれ、必須出典区間を含むケースが各回90%以上。
  実モデルの全順序一致は要求しない。precision と誤取得件数は報告指標とする。
- 該当なしは空結果だけを合格とし、各分類・各回70%以上。
- 6項加重和、係数合計1、新しさ係数0.1以下。
- 独立した tuning 82件・acceptance 55件を各3回。安全違反0の設定から、分類・回ごとの最低想起合格率、
  最低該当なし合格率、平均 recall の順で選び、完全同率なら固定グリッド先頭を選ぶ。acceptance は調整に戻さない。

### memory-v2（2026-10-20、全構成 FAIL）

reranker は全適格候補の順位だけを変え、棄却には6項合成スコアの閾値を使った。
返却予算は最大5件・UTF-8 1,500byte を1,500トークン相当とする推定とした。

bge-m3 Q8_0 / CLS / 1024次元と Qwen3-Embedding-0.6B Q8_0 / last / 1024次元を、
pg_bigm / PGroonga、bge-reranker-v2-m3 の有無で比較した8構成はすべて品質未達だった
（[実測結果](../reports/2026-10-20-retrieval-it2-v2.md)、[候補情報](../reports/2026-10-20-retrieval-it2-v2-models.json)）。
正解と非正解の6項スコアが重なり、想起を保つ閾値では非正解も通過した（unrelated 0/10、threshold 0/1）。
固定長文の必須返却片は1,500byte 予算を超えた（長文0/1）。この FAIL は記録として保持する。

### memory-v2.1（2026-10-21）

memory-v2 の未達を受けて、次の条件で新しい比較版を固定した。

- 6項加重和は候補の取得順位に使い、上位20件を reranker に渡す。
  reranker ありでは raw relevance が閾値未満の候補を棄却し、残りを relevance 降順・同点 ID 順で返す。
  閾値は -12〜12 の1刻みとし、合成スコア用グリッドとは分ける。reranker なしは従来の6項閾値を使う。
- 返却予算は最大5件・1,500トークン相当とし、埋め込みモデルの tokenizer（`POST /tokenize`）で返却 JSON 全体を数える。
  派生記憶に対応する逐語出典範囲を返し、予算を超える区間は検索一致箇所を含む窓と切り出し情報で示す。
  必須出典の欠落は品質失敗とし、安全条件・gold は緩めない。

- reranker ありの4構成は品質指標が一致した。選択値は raw relevance 閾値 -2、6項重みは

  paraphrase と cross_language が各9/10で、ゲート下限ちょうどだった。

  製品 HTTP・ProvisionRecord 書込み・実運用規模の性能はこの観測から確定しない。

## 決定

- 埋め込みは **bge-m3 Q8_0 / CLS / 1024次元** とする。固定 revision・SHA-256 は[候補情報](../reports/2026-10-20-retrieval-it2-v2-models.json)に従う。
- 全文検索は **pg_bigm** とする。
- reranker は **bge-reranker-v2-m3** を使い、memory-v2.1 の役割分担とする。
  6項加重和の上位20件を reranker に渡し、raw relevance が閾値未満の候補を棄却する。
- 初期値は6項重み semantic=0.55・lexical=0.25・他4項各0.05、relevance 閾値 -2 とする。
  閾値と重みは設定値とし、変更する場合は新しい比較版の独立評価で確認する。
- 返却予算は最大5件・1,500トークン相当とし、採用埋め込みモデルの tokenizer で返却 JSON 全体を数える。
  予算を超える出典区間は、検索一致箇所を含む窓と切り出し情報で返し、逐語の内容を言い換えない。
- vector はモデル・digest・次元を識別子として持ち、別モデルの空間を混ぜない。

## 検討した案

- **reranker なし**：想起は100%だが、該当なしを空にできずゲートを満たさないため採用しない。
- **Qwen3-Embedding-0.6B**：品質指標は bge-m3 と同じだったが、p95 がやや高く、既存の基準モデルである bge-m3 を継続する。
  宣言文脈長32,768の全域は評価していない。比較候補として保持する。
- **PGroonga**：品質は pg_bigm と同じで、memory-v2 の合成索引は約33.4 MiB と pg_bigm（16 KiB 程度）より大きかった。
  合成ケースの小さな索引だけで実運用の資源差は断定しないが、品質差がないため軽い pg_bigm を選ぶ。
- **ruri-v3-310m**：公式 GGUF がなく未実行。未確認の変換・代替で補わない。
- **multilingual-e5-large**：以前の固定長文試験で入力上限512の制約があり、比較対象外とした。

## 影響

- reranker の常駐モデルが増え、想起の処理時間は reranker なしより約2倍になる（ハーネス内 p95 で約20ms 増）。
- 想起分類の一部は合格下限ちょうどで、relevance 分布は正解と該当なしで重なる。
  ケースの追加・実会話の傾向で想起または該当なしが下限を割る可能性があり、閾値は設定値として監視・再評価する。
- 製品の想起 API は、この ADR の埋め込み・全文検索・reranker・予算計数を使う。
  製品 HTTP 全体と実運用規模の遅延は、別途 ADR 0017 の予算に対して測定する。
- 再評価は新しい比較版を固定して行い、memory-v2 の FAIL と memory-v2.1 の結果を保持する。

## 追補（2026-10-28、本人決定）：長い原文のチャンク索引

[入力長の診断](../reports/2026-10-28-recall-input-length-diagnosis.md)で、長い本文を1件の索引文書として
埋め込み・lexical 照合・rerank すると、遅延が増え、長文の一部だけにある事実が全体の意味に薄まることが分かった。
これを受けて次を採用する。

- 原文 Turn は正本としてそのまま保持する。チャンクは索引用の派生物で、正本を置き換えない。
- 長い索引文書は、前後に重なりを持たせたチャンクに分け、チャンクごとに vector と lexical 用の正規化テキストを持つ。
  チャンクに収まる短い文書（音声会話100文字・テキスト256文字の段階を含む）は従来どおり1件のままとする。
- reranker にはチャンクのテキストを渡す。
- 同じ索引文書から出た複数チャンクは、返却前に1件へまとめ、上位5件を同じ原文で占めない。
- 返却する本文は原文 Turn から切り出す逐語区間とし、一致したチャンクを含む窓と切り出し情報で示す。
  チャンクの境界で文脈を失わないよう、窓は原文側で取る。
- チャンク長・重なりは設定値とし、新しい比較版で固定して評価する。

結果が変わる変更のため、memory-v2.1 と同じ品質ゲートを新しい比較版で独立に満たすことを採用条件とする。
比較版には、長文の一部にだけある事実を問うケースと、指示語を含む文脈依存のケースを追加する。
memory-v2.1 の結果は保持し、再評価で上書きしない。

性能対策のうち、lexical の bigram 数の上限と rerank 入力の切り詰めも結果が変わる。
この2案はチャンク索引と性能確認の後に要否を判断する追加対応として保留する。

## 追補（2026-10-30、本人回答 Q-008・Q-009）：閾値の既知の限界と保留した性能対策

memory-v2.1 と memory-v2.2 の tuning では、採用値の閾値 −2 で「閾値付近・該当なし」が各回 4/6 となり、
基準の 70% に届かない（[チャンク索引の評価](../reports/2026-10-29-recall-chunk-eval.md)）。
該当しない短い1文の記憶が、閾値をわずかに超える関連度（−1.91、−0.15）で返る。
選定規則が想起の取りこぼしを最優先するため −2 が選ばれており、acceptance は両版とも満たしている。

- Phase 1 は閾値 −2 を維持し、この tuning の基準未達を既知の限界とする。
  同じ重みで閾値を −1 または 0 に上げると、言語をまたぐ想起の取りこぼしが1件生じる。
- 閾値と選定規則の見直しは、tuning のケースを増やしたうえで Phase 2 で新しい比較版として再評価する。
  acceptance を調整に戻さない（[#128](https://github.com/FYuki/digital-souls-memory/issues/128)）。
- 2026-10-28 の追補で保留した bigram 数の上限と rerank 入力の切り詰めは、Phase 1 では導入しない。
  チャンク索引後の段階別 ST で、音声会話100文字・テキスト256文字は ADR 0017 の必達 p95 を満たしている。
  p50 の目標（[#112](https://github.com/FYuki/digital-souls-memory/issues/112)）や
  10000件規模（[#114](https://github.com/FYuki/digital-souls-memory/issues/114)）の対策を検討するときに、
  要否を判断し直す（[#123](https://github.com/FYuki/digital-souls-memory/issues/123)）。
