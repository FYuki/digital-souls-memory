# 0021. 検索方式・埋め込みモデルの比較（採用保留案）

- 日付：2026-10-20
- 状態：Proposed

## 背景と比較条件

永続ストア PostgreSQL + pgvector と共存する日本語全文検索方式、埋め込みモデル、
任意の reranker の採否を検討する。判断の基準は **memory-v2** とする。
取りこぼさないことを優先し、スコアはレンジで評価する。

- 安全は各分類・各回100%。検索前の適格性、禁止情報の不在、原文区間・出典・話者・言語、返却予算を守る。
- 想起分類は、必須正解すべてが上位5件に含まれるケースが各回90%以上。
  実モデルの全順序一致を要求しない。precision と誤取得件数は報告指標とする。
- 該当なしは空結果だけを合格とし、各分類・各回70%以上。threshold の正解あり側・該当なし側を分ける。
- 6項加重和、係数合計1、新しさ係数0.1以下。最大5件・UTF-8 1,500byteを1,500トークン相当とする推定予算。
- 独立した tuning 82件・acceptance 55件。固定45設定を各3回。
  安全違反0の設定から、分類・回ごとの最低想起合格率、最低該当なし合格率、平均 recall の順で選び、
  完全同率なら固定グリッド先頭を選ぶ。acceptance は調整に戻さない。
- reranker は全適格候補の順位だけを変え、棄却には6項合成スコアの閾値を使う。
  正解・非正解スコアの最小・p05・p50・p95・最大を分類別・各回で確認する。

## 観測結果

bge-m3 Q8_0 / CLS / 1024次元と、Qwen3-Embedding-0.6B Q8_0 / last / 1024次元を、
pg_bigm / PGroonga、bge-reranker-v2-m3 の有無で比較した。
モデルの固定 revision・SHA-256・接頭辞・文脈長は[候補情報](../reports/2026-10-20-retrieval-it2-v2-models.json)と
[実測結果](../reports/2026-10-20-retrieval-it2-v2.md)を参照する。

| 埋め込み / reranker | 全文検索 | 品質 | p95 ms（各回の範囲） |
| --- | --- | --- | --- |
| bge-m3 | pg_bigm | FAIL | 16.55–22.17 |
| bge-m3 | pgroonga | FAIL | 18.30–20.84 |
| bge-m3 + reranker | pg_bigm | FAIL | 34.85–38.89 |
| bge-m3 + reranker | pgroonga | FAIL | 36.82–41.35 |
| Qwen3-Embedding-0.6B | pg_bigm | FAIL | 16.04–20.32 |
| Qwen3-Embedding-0.6B | pgroonga | FAIL | 15.99–18.49 |
| Qwen3-Embedding-0.6B + reranker | pg_bigm | FAIL | 36.20–43.82 |
| Qwen3-Embedding-0.6B + reranker | pgroonga | FAIL | 36.03–37.28 |

全構成・各回で安全100%、同義語・言い換え・日英横断は各100%。
長文以外の想起分類も100%だったが、長文0/1、unrelated 0/10、threshold の該当なし0/1で品質未達。
precision は case 平均0.4667、誤取得57件/回。reranker による品質改善は見られなかった。
固定 tuning でも全ゲートを満たす設定はなかった。

選定は両モデル・両方式・reranker 有無とも、semantic=0.55・lexical=0.25・
recency/importance/self_relevance/trust 各0.05、閾値0.20となった。
想起を保つ低閾値では非正解も通過し、閾値を上げると想起を失う。
正解と非正解の6項スコアは重なり、順位のみを変える reranker は棄却に使われない。
この条件の結果を reranker 一般の有効性の否定へ広げない。

固定長文は両埋め込みモデルで受理されたが、必須返却片が4,060byteで1,500byte予算を超えた。
閾値以上の正解も返却段階で除外される。元の区間を維持したままではモデル・閾値だけで解消しない。
安全100%や速い検索で、長文・該当なしの未達を相殺しない。

ハーネス内の想起 p95 は全回で目標300ms・必達600ms以内だった。
製品 HTTP・ProvisionRecord 書込み・実運用規模の性能はこの観測から確定しない。
pg_bigm の小さな合成索引は16 KiB程度で、PGroonga の約33.4 MiBより小さかった。
モデル間では DB image の hash が異なるため、小さな時間差をモデル固有の優位性と断定しない。
同じモデルの reranker 有無比較は同一 DB image を使った。

## 検討した案と推奨

**採用は保留する。** 必須の品質ゲートを満たすモデル・全文検索・reranker の組み合わせはない。

- 次の比較基準は **bge-m3 Q8_0 / CLS / 1024次元 + pg_bigm、reranker なし** とする案。
  重みは semantic=0.55・lexical=0.25・他4項各0.05、閾値0.20。
  既存の基準モデルを継続でき、全文検索方式の品質差はなく、合成索引の資源は pg_bigm が軽かった。
  この値は品質合格の採用値ではない。該当なし・長文の未達を解消するまで製品採用へ進めない。
- **Qwen3-Embedding-0.6B** は比較候補として保持する。同じ品質と低い p95 の観測があるが、
  現条件のゲート未達を解消していない。宣言文脈長32,768の全域を評価した結果ではない。
- **reranker あり** は、今回の順位だけの条件では品質を変えず、追加の常駐モデルと処理時間を要した。
  棄却方式を変える比較は条件を別に定める。
- **ruri-v3-310m** は公式 GGUF がなく、今回の品質比較は未実行。未確認の変換・代替で補わない。
- **multilingual-e5-large** は以前の固定長文試験で上限512の実行制約があり、今回の比較対象外。
  過去の[比較記録](../reports/2026-10-20-retrieval-it2-host.md)と memory-v1 の証跡を保持する。

## 採用判断の条件

1. 原文区間の保持と1,500byte推定予算を両立する条件を明確にする。
   長文の必須返却片を含められない状態を、正解の削除や暗黙の切り詰めで合格に変えない。
2. 想起を保ちながら該当なしを各回70%以上にできる棄却方式を比較する。
   reranker score 等による no-match 判定を検討する場合も、6項スコアと安全条件の意味を明示する。
3. 安全各回100%・想起各回90%以上・該当なし各回70%以上を同時に満たす独立評価を確認する。
   条件を変更するなら新しい比較版として固定し、今回の FAIL を保持する。
4. 合成ケースの小さな索引・局所的な遅延差だけで実運用方式を決めない。
   比較資源の再現性、ケースの出典・配布条件、製品全体の性能はそれぞれ確認する。

採用モデル・次元・全文検索方式は未確定。本書は推奨案であり、承認済みの採用決定ではない。
