# 0017. 想起 API は2種類とし、毎ターンの想起は目標 p95 300ms・必達 p95 600ms を仮の予算とする

- 日付：2026-10-20
- 状態：承認（数値は仮値。実測で見直す）

## 背景

音声会話では、ユーザーの話し終わりからキャラクターの話し始めまでの目標値を2秒、必達値をその2倍の4秒とする（2026-10-20 のユーザー決定）。この区間には、話し終わりの判定、音声認識の確定、記憶の想起、応答生成の最初の文、音声合成の最初の音声が含まれる。

## 決定

- 想起 API は次の2つを持つ。
  - **常駐コンテキスト API**：CoreIdentity、Temperament、PersonalityProfile の記述文、active な Motivation、CharacterProfile、VoiceExemplar の候補を返す。セッション開始時に呼び、Core がキャッシュする。自動の人格更新は進行中のセッションに反映せず、次のセッション開始時に新版を取得する（0011）。毎ターンは呼ばない。
  - **ターン想起 API**：直近の発話をもとに派生記憶を検索し、原文区間と VerbatimAnchor を返す。組み立て済みのコンテキスト片と、素材（記憶・原文の一覧）のどちらで返すかを指定できる。
- 目標値2秒の内訳は従来の配分を維持し、必達値は各区間を2倍とする。数値は仮値であり、実測で見直す。検索件数・トークン上限は設計上の暫定値であり、実測やユーザーが個別に指定した値ではない。

| 区間 | 目標値 | 必達値 |
| --- | --- | --- |
| 話し終わりの判定 | 500ms | 1,000ms |
| 音声認識の確定 | 200ms | 400ms |
| ターン想起（Memory の処理と通信） | 300ms | 600ms |
| 応答生成の最初の文 | 700ms | 1,400ms |
| 音声合成の最初の音声 | 300ms | 600ms |
| 合計 | 2,000ms | 4,000ms |

- ターン想起の目標値は p50 150ms／p95 300ms、必達値は p95 600ms とする。目標値の内訳の目安は、検索文の embedding 80ms、ベクトル検索と全文検索 100ms、スコア計算・原文区間の取得・提供記録の書き込み 70ms、通信 50ms。
- 返す量は記憶5件まで、原文区間を含めて 1,500 トークン相当までとする。
- Core は目標の2秒を守るため、ターン想起を 400ms で打ち切り、記憶なしで応答を続ける。必達の4秒は打ち切り後の経路でも満たす。打ち切りは Core 側の責務で、Memory は遅延を記録する。

## 検討した案

以下は今回の決定と代替構成の比較説明であり、過去に各案が明示提案されたことを示す記録ではない。

- **常駐コンテキストも毎ターン返す**：変化が遅い情報を毎ターン転送すると予算を圧迫するため、キャッシュ前提にした。
- **想起を待ってから応答する（打ち切りなし）**：2秒の目標を守れないため不採用。

## 影響

- 音声認識の途中結果で想起を先に始めるかどうかは Core の判断とする。先に始めれば想起の時間を話し終わりの判定と重ねられる。
- p95 が予算を超え、索引のチューニングでも戻らないときは、0007 の Qdrant への切り替え条件を評価する。
- 性能試験（ST）の合否は必達値で判定し、目標値は計測して推移を記録する。実測で数値を見直す。
