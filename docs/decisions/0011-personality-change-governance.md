# 0011. 性格の変更は審査エージェントの承認と ChangeBudget を経る

- 日付：2026-10-19
- 状態：承認

## 背景

内省の結果をそのまま人格に書き込むと、単発の出来事や LLM の思い込みで性格が急変し、提案と撤回を繰り返して振動する。経験による人格変化は弱く、無関係な会話を挟むと方向が保たれないことが多い（"Do AI Personas Grow?", 2026）。

## 決定

- 性格の変化は「観察 → 内省 → 信念（Belief）→ 変更提案 → 審査 → 新版」の順に進め、段を飛ばさない。事実の更新は性格を直接変えない。
- 変更提案の審査は審査エージェントが行う。審査エージェントは内省を生成したエージェントとは別のコンテキストで動かし、提案と根拠の原文だけを渡す。判定は CoreIdentity との矛盾、根拠の原文が主張を支えているか、ChangeBudget の充足の3点で行い、却下理由も記録する。
- ChangeBudget は、根拠となる独立した原文の数、持続確認のサイクル数、1回あたりの変化量の上限、学習率、期間あたりの累積上限、クールダウン、転機の例外条件で構成する。数値は開始値で運用を始め、運用中に評価指標を見て調整する。
- 変更種別は gradual／turning_point／author_seed（初期登録）／rollback（以前の版へ戻す）とする。作者による自由な数値修正は設けない。rollback は審査の誤判定や記憶汚染で誤った変更が通ったときの復旧に使い、理由を IdentityHistory に残す。
- 承認された変更は進行中のセッションには反映せず、次のセッションから使う。

## 影響

- 作者は承認ログを後から確認し、問題があれば rollback する。転機の例外承認だけを作者に通知する。
