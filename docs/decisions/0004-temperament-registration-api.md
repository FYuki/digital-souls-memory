# 0004. 気質とコア人格は登録APIでキャラごとに保持し、Card は取り込まない

- 日付：2026-10-19
- 状態：承認

[0015](0015-core-and-memory-boundary.md) により、本記録の「利用サービス」「利用側」は Core を指す。

## 背景

キャラクターの一貫性は、不変の気質、性格、記憶、内省による動機付けで構成される。中央のキャラ設定（Card）には声・見た目・世界設定など人格以外の設定も含まれる。気質は内省・記述変換・審査で毎回入力として使う。

## 決定

- 本サービスは Temperament（気質）と CoreIdentity の価値観・禁止事項を正本として持つ。
- これらはキャラごとに登録APIで登録・更新し、版と登録日時を記録する。内省・記憶・夢見処理からは変更できない。
- Card は丸ごと取り込まない。声・見た目・世界設定は Card に残す。
- ロック機構は持たない。Card 更新時に登録APIを呼んで同期するのは利用サービス側の責務とする。

## 検討した案

旧ドメインモデルの A2 は、人格の4要素（気質・性格・記憶・内省と動機）を本サービスの正本とし、Card は人格以外を持って character_id で参照する案であった。最終決定では Card を丸ごと取り込まず、気質と CoreIdentity の価値観・禁止事項を登録APIで受け取り、同期は利用側の責務とした。Card 参照やロックの具体的な代替方式を比較した記録はない。

## 影響

- 気質の参照は本サービス内で完結し、判定に使った版を追跡できる。
- Card と本サービスの内容がずれないよう、利用サービス側で同期を実装する必要がある。
